4. HALLAZGOS
--------------------------------------------------------------------------------
H-01 (CRÍTICO) — El endpoint dedicado de expulsiones no puede registrar.
  POST /api/examenes/838/expulsiones devuelve 409/500. Causa:
  "null value in column \"idincidencia\" of relation \"expulsion\" violates
  not-null constraint". RegistroExpulsionService.registrar guarda la expulsión
  antes de asignar idIncidencia; IncidenciaService.registrar hace flush y dispara
  el NOT NULL. Si el estudiante ya está retirado, falla antes con el mensaje de
  duplicado. El flujo de UI funciona porque crea primero la incidencia y la
  cierra. Afecta a TC-009 (flujo alternativo), TC-014/TC-017 (endpoint directo) y
  a cualquier integración que use el endpoint dedicado.

H-02 (CRÍTICO) — Concurrencia: una expulsión se pierde con HTTP 500.
  Dos POST simultáneos: 838 -> 201 (INC-090/expulsión 21); 849 -> 500
  "could not serialize access due to concurrent update" en
  hu15_cabeza_cadena / hu15_sellado_nuevo_evento(). El trigger de auditoría
  actualiza un singleton con UPDATE ... RETURNING y no hay reintento; la
  transacción falla. No hubo registros parciales, pero se perdió una expulsión.
  Afecta a TC-016.

H-03 (CRÍTICO) — El administrador puede registrar expulsiones.
  La UI del administrador muestra "Incidencia" y "Expulsar al estudiante del
  examen"; con el examen 849 y el estudiante 202212881 el checkbox se habilitó.
  SecurityConfig permite ADMINISTRADOR y el servicio no lo restringe; el POST
  directo devuelve 409, no 403. Afecta a TC-035 y TC-036.

H-04 (ALTO) — Validación de servidor incompleta en solicitudes directas.
  - Parámetros obligatorios ausentes (tipo/severidad/descripción) -> HTTP 500,
    no 400; la descripción corta sí devuelve 400.
  - El POST /api/incidencias aceptó al estudiante 99000133, que la búsqueda
    devuelve como NO_INSCRITO, porque tenía un ingreso existente. El endpoint de
    registro no valida la inscripción; la UI sí bloquea la selección.
  - El endpoint de búsqueda devuelve puedeRegistrarIncidencia=true para un
    estudiante RETIRADO (Fabricio); la UI lo bloquea, pero el flag del backend es
    inconsistente con el mensaje "no se pueden registrar más incidencias".
  Afecta a TC-002, TC-004 y TC-036.

  SeccionIncidencias.fnExportarExcel envía idExamen, idAmbiente, tipo, estado y

5. EVIDENCIA TÉCNICA DESTACADA
--------------------------------------------------------------------------------
5.1 Error del endpoint dedicado (H-01)
  POST /api/examenes/838/expulsiones -> 409
  Mensaje/causa: null value in column "idincidencia" of relation "expulsion"
  violates not-null constraint.
  El flujo UI (POST /api/incidencias con retirarEstudiante=true + PATCH de cierre)
  sí crea la incidencia y la expulsión.

5.2 Error de concurrencia (H-02)
  ERROR: could not serialize access due to concurrent update
  Contexto: UPDATE public.hu15_cabeza_cadena SET secuencia = secuencia + 1
